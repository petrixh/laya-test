Laya Under Test

Laya is a 421M non-autoregressive decision model: you hand it a state and typed questions, and one forward pass returns calibrated probabilities. We containerised it, measured it on Banking77, and then made it play a browser game where a wrong answer is visible as a reindeer hitting a wall. It is very good at one shape of question and unable to do another, and the difference is sharper than the headline benchmarks suggest.

Works

Classifying one described thing

Given a short state and a handful of options, the model is strong and well calibrated — but only while the option list is small. Accuracy falls off a cliff between 8 and 16 labels, and calibration fails faster than accuracy does.

Mean input tokens plateau at 189 as k grows, against an option budget of roughly 192 — the cliff is the option list being truncated, not a reasoning limit.

Three different confidence regimes

Calibrated probability is the product's whole pitch, and it behaves in three distinct ways depending on what you ask. Treating confidence as a single trustworthy signal is the biggest trap here.

Confidence lies under option truncation, tells the truth when the model is out of its depth, and goes quiet even when the model is perfect. Validate it per task or do not gate on it.

Works

Framing moves accuracy more than anything else

The first attempt at the game scored 0.35 against a 0.33 chance baseline and answered “duck” to every obstacle. The same model on the same scenes, after a sweep of 192 prompt variants, scores 40/40. Nothing about the task changed — the state still only names the object.

Three things carried that improvement, and all are reusable. Putting the domain knowledge in the criteria is the largest single lever. The words jump and duck as label keys were actively harmful — the decision head reacts to the label tokens themselves, so an evocative name fights its own description. And a third option cost 0.14 even when it was semantically reasonable.

Option count is the sharpest edge on this model. When a third class appeared later, the fix was a second question rather than a third label.

Breaks

Ranking alternatives returns nothing

Describe two options in the state and ask which to take, and the model answers by option position. The clean test needs no baseline: ask the same question with the two options swapped. A model reading the state names the same one twice.

It holds even for barrier-versus-clear, where one option is a wall and the other is empty. Alternatives belong in the criteria, one question per thing — which is exactly how the working classifier is built.

Method

Two mistakes worth copying

A score without a baseline is not a score

The first sweep of the lane question reported 0.875 “picks a passable lane” and we nearly shipped it. A constant strategy — always answer “left” — scores 0.825 on the same scenes. The margin was noise, and the sweep had been measuring how often the left lane happens to be passable.

A safety filter can hide a dead component

Restricting the choice to lanes the model had already certified safe took the run from nine crashes to zero. The chooser still contributed nothing — it took the first option offered in 18 of 18 choices — but survival was now inherited from the classifier upstream. A shielded component that never fails is not evidence that it works.
